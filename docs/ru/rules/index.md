# Обзор правил

Плагин предоставляет 4 правила для соблюдения методологии Feature-Sliced Design:

| Правило | Описание | Фикс |
|---------|----------|------|
| [layers-slices](./layers-slices) | Проверяет импорты между слоями согласно иерархии FSD | |
| [absolute-relative](./absolute-relative) | Проверяет тип пути (относительный/абсолютный) | |
| [public-api](./public-api) | Требует импорты только из public API | 💡 |
| [import-order](./import-order) | Сортирует импорты по слоям FSD | 🔧 |

**Легенда:**
- 🔧 Автоматически исправляется с `--fix`
- 💡 Имеет предложения по исправлению (suggestions)

## Иерархия слоёв FSD

Правила работают со стандартной иерархией слоёв FSD (от нижнего к верхнему):

1. `shared` — переиспользуемые утилиты, UI kit (без слайсов)
2. `entities` — бизнес-сущности
3. `features` — пользовательские взаимодействия
4. `widgets` — композиционный слой
5. `pages` — страницы приложения
6. `processes` — сложные бизнес-процессы (устарел)
7. `app` — инициализация приложения (без слайсов)

::: info
Слои `shared` и `app` не имеют слайсов — они содержат модули напрямую.
:::

## Сегменты FSD

Стандартные сегменты внутри слайсов:
- `ui` — UI компоненты
- `model` — бизнес-логика
- `lib` — утилиты
- `api` — взаимодействие с API
- `config` — конфигурация
- `assets` — статические ресурсы
